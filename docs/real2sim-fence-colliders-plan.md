# Real2Sim: using the Blender track model with working fence colliders

**Status — 2026-10-18: plan only, nothing implemented.**

The goal is to see the Blender-built track (`track.fbx`) in the
`real2sim-home-track` scene, with fences the car crashes into exactly where
the model shows them.

Sibling files:

- `scripts/real2sim/build_blender_model.py`: builds `track.fbx` from
  `layout.json` + `mat.png`.
- `unity/Assets/Scripts/Real2SimCourse.cs`: builds the scene's walls
  (`Curb`) and goal gates from `layout.json`.
- `unity/Assets/Real2Sim/home-track/layout.json`: the measured track.

---

## Part 0 — How things stand

`track.fbx` is **not placed in the scene**. Everything the car interacts
with is generated by `Real2SimCourse` at edit time and again on Play:

- one box collider per fence panel, named `Curb`, 0.2 sim units thick, on
  the `Default` layer;
- goal triggers `Goal-1..Goal-N` along the centerline.

The model's fence is 44 `Panel-*` sheets (43.2 x 35 cm, 4 mm thick), 44
`Post-*` cylinders and 44 `PostCap-*` spheres under a `Fence` empty, built
in real meters from `layout.json`'s `fence_panels`.

A fence collider only works if all three of these hold:

1. **Name contains `Curb`.** `CarController.OnCollisionEnter` only records
   a crash for objects whose name contains `Curb` (or a rail/rock name).
   Any other collider stops the car without ending the episode, so the
   collision is never recorded as a crash.
2. **Thick enough.** At sim scale (about 16.6x, see
   `Real2SimCourse.scale`), a 4 mm panel is far too thin. The car can pass
   through it in a single physics step. The generated walls are 0.2 sim
   units thick for this reason.
3. **On the `Default` layer.** The car's distance sensors (SphereCasts in
   `CarController.layerMask`) only see this layer.

There is also a **geometry mismatch**. `Real2SimCourse.innerBarrierInset`
(default 0.05 m) pulls the inner barrier ring 5 cm inwards at runtime to
widen the lane. `build_blender_model.py` reads the same `layout.json` but
knows nothing about the inset, so the model's inner fence sits 5 cm outside
the colliders.

Unity's "Generate Colliders" import option is not a fix. It creates mesh
colliders that keep the mesh names (fails rule 1) and the 4 mm thickness
(fails rule 2).

---

## Part 1 — Recommended: the model is visual, `Real2SimCourse` owns physics

The colliders keep coming from `layout.json`, and only one script makes
them. The model only adds looks.

### Step 1 — Put the inset in one place

The inset currently exists only in `Real2SimCourse.cs`. Move it to a
`layout.json` field (e.g. `"inner_barrier_inset": 0.05`) that both readers
apply:

- `Real2SimCourse.ShapeLane` uses the layout value when it is present. The
  inspector field stays as an override.
- `build_blender_model.py` applies the same inset to the inner ring before
  building panels and posts. Identify the ring the same way as the C#:
  panels with both ends more than 0.15 m inside the mat edge, with
  endpoints on the ring's bounding-box sides moved inwards.

The alternative is to bake the shrunken coordinates into `layout.json`'s
`fence_panels` directly. That is simpler, but the file then no longer
records the measured real-world fence.

### Step 2 — Rebuild the model

```
blender -b --python scripts/real2sim/build_blender_model.py -- unity/Assets/Real2Sim/home-track
```

This rewrites `track.fbx` and the files in `blender~/` (`track.blend`,
`track.glb`, `preview.png`).

### Step 3 — Place it in the scene

Have `Real2SimCourse.Generate()` instantiate the model as a child of the
course, so it is rebuilt with everything else and cannot drift:

- new inspector fields: `public GameObject trackModel` (the `track.fbx`
  asset) and `public bool showTrackModel = true`;
- scale `scale` (about 16.6) uniformly, place the mat corner at the course
  origin, put the model at `trackY`;
- strip any colliders from the instance, so the model can never collide.

**Verify the axes when you first do this.** The FBX is exported with
`bake_space_transform=True`, Blender's Y becomes Unity's Z, and the import
may mirror X. Check by turning both `showBarriers` and the model on and
confirming the generated walls sit inside the model's panels at all four
outer corners and all four inner corners. Fix the instance rotation or
scale sign until they do.

### Step 4 — Hide the generated walls

Untick `showBarriers` (and optionally `showGoals`). The `Curb` colliders
and goal triggers stay active, so crashes and goals are still counted.

### Step 5 — Check

- Play with `showBarriers` on and the model on. The grey walls should
  cover the model's panels everywhere.
- Run a short demo job (Demo transitions about 5000) and check the trainer
  log: crashes in `[crash-pos]` lines should only happen where the car
  visibly touches a fence.
- Edit `layout.json`, rebuild the model, and confirm both still match.

## Part 2 — Alternative: colliders on the model at import

Only worth doing if the model should become the single source of truth,
e.g. if it gets hand-edited in Blender and drifts from `layout.json`.

1. Add an editor `AssetPostprocessor` (e.g.
   `unity/Assets/Scripts/Editor/Real2SimTrackPostprocessor.cs`) that acts on
   `Real2Sim/*/track.fbx` in `OnPostprocessModel`.
2. For each `Panel-*`: add a `BoxCollider` sized to the mesh bounds, with
   thickness raised to at least 0.2 sim units (that is about 0.012 m before
   scaling), and the name changed to `Curb-Panel-N` (or the collider put on
   a child called `Curb`). Set the layer to `Default`.
3. For each `Post-*`: the same, so the 1.8 cm gaps between panels at the
   posts are closed. `PostCap-*` needs no collider.
4. Turn off `Real2SimCourse`'s wall generation (a new `generateWalls`
   flag) but keep its goals. Otherwise every fence is collided with twice.
5. The inset must then live in Blender (Part 1, Step 1), because
   `ShapeLane` would no longer move any colliders.

Drawbacks: colliders now come from two places, the importer and the course
script. The postprocessor reruns on every reimport. Collider sizes depend on
the FBX import scale, which needs pinning in the import settings.
